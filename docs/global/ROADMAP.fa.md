# نقشه راه، کارها و تصمیم‌های باز

**وضعیت:** برنامه کاری اولیه بر اساس دامنه v1.12 و تصمیم‌های تازه مالک محصول؛ برنامه زمانی یا تعهد انتشار نیست. تاریخ و مالک نام‌برده تعیین نشده‌اند. ترجمه‌پیش‌نویس نیازمند بازبینی است.

## ترتیب تحویل

1. **پایه پروژه — پیش‌نویس اولیه مستندات آماده است:** حاکمیت، معماری پیشنهادی، سیاست‌های امنیت/داده/کیفیت، ۱۳ راهنمای دوزبانه سرویس، پیش‌نویس‌های دوزبانه اسناد سراسری و ردیابی الزامات ایجاد شده‌اند. بازبینی انسانی/فنی و تصویب مالک محصول هنوز لازم است؛ این به معنی پیاده‌سازی نیست.
2. **کاشی برداری — نخستین اولویت پیاده‌سازی:** انتشار نخست فقط برداری؛ تمرکز آزمون پنج شهر تهران، کرج، تبریز، مشهد و اصفهان؛ پشتیبانی از داده عمومی و خصوصی و هدف هر دو مدل میزبانی. قالب، داده، نقش و عملیات هنوز باید تعیین و آزموده شوند. آزمون پنج شهر، پوشش یکسان سراسر کشور را ثابت نمی‌کند.
3. **مسیریابی — اولویت بعدی:** جهت مصوب مالک برای انتشار نخست، هر دو OSRM و Valhalla با انتخاب سازمانی است. هر دو باید برای خودرو، پیاده، دوچرخه، ترتیب ورودی، سفر چندمقصده و بهینه‌سازی اختیاری زمان آزموده شوند. شکاف امکان‌پذیری پیش از انتشار به تصمیم مالک نیاز دارد.
4. **بقیه سرویس‌ها — مرحله‌ای:** برای هر سرویس امکان، داده و مجوز بررسی شود؛ ترتیب و زمان انتشار تعیین نشده‌اند. حمل‌ونقل عمومی، ترافیک زنده، لجستیک پیچیده و ناوبری آفلاین نیازمند تصمیم و داده معتبرند.

## کارهای پایه

- [x] پیش‌نویس مرجعیت اسناد، واژگان وضعیت و ردیابی الزام؛ تصویب مالکان و مسئول بازبینی باز است.
- [x] ثبت مبنای به‌تعیین مالک: Bun، TypeScript Strict، Vitest، Fastify و Zod؛ نسخه‌های دقیق و بررسی هر adapter در فایل قفل Bun ثبت شوند.
- [x] انتقال نمونه‌های موجود از JavaScript و test runner داخلی Node به TypeScript Strict و Vitest زیر Bun.
- [x] نمونه محدود سازگاری Bun/Fastify/Zod با Vitest اجرا شد؛ adapter برای استفاده تولیدی تصویب نشده است.
- [x] ایجاد فرایند و الگوی ADR و فهرست تصمیم‌ها؛ انتخاب‌های خودشان تا تصویب باز می‌مانند.
- [x] ایجاد راهنمای اولیه مدل تهدید، شناسنامه داده، بازبینی امنیت/حریم خصوصی و شواهد انتشار؛ بررسی رسمی باز است.
- [x] افزودن CI برای نمونه‌ها: نصب قفل‌شده Bun، بررسی TypeScript Strict، Vitest و audit وابستگی تولیدی؛ در صورت افزودن API نمونه‌سازی گسترش یابد.
- [x] افزودن بررسی ساختار مستندات، پیوندها و شناسه الزامات با آزمون واحد.
- [ ] بازنگری جداگانه دامنه محصول در نسخه جدید و دوزبانه؛ v1.12 درجا بازنویسی نشود.

## کارهای کاشی نقشه

- [x] جهت محصول: برداری، پنج شهر برای تمرکز آزمون، عمومی و خصوصی، دو مدل میزبانی، نسخه تغییرناپذیر و بازگشت.
- [x] نمونه‌سازی TypeScript غیرتولیدی برای ماتریس نامزد Web Mercator XYZ ساخته شد؛ ماژول محاسباتی آن وابستگی اجرایی بیرونی ندارد و هفت آزمون Vitest مرز/محدوده/تبدیل موفق‌اند. این انتخاب قالب یا API نیست.
- [ ] ADR-0001 پیشنهادی بازبینی و مسئول محصول/فنی/داده/امنیت برای نمونه‌سازی گسترده تعیین شود.
- [ ] رمزگذاری payload، ماتریس/شماره‌گذاری، قرارداد ارائه و قالب ذخیره‌سازی جداگانه مقایسه؛ سپس بزرگ‌نمایی، جزئیات واقعی و معنای خالی/خارج پوشش پیشنهاد شوند.
- [x] نمونه GeoJSON مصنوعی و نمونه رمزگذاری/بازخوانی MVT جدا ساخته شد؛ سیزده آزمون فعلی برش مرزی خط/چندضلعی، حفظ یک حفره داخلی مصنوعی، برش مؤلفه چندضلعی چندبخشی و بررسی نامزد شِما، `source-layer` و ارجاع ویژگی MapLibre، از جمله نمونه منفی ویژگی ناشناخته، را هم شامل می‌شوند؛ رندر واقعی نیستند. داده OSM یا موقعیت شخصی استفاده نشده است.
- [ ] پیش از ارزیابی استخراج OSM یا ادعای پوشش، نمونه مرجع واقعی و مجاز فراهم شود؛ نمونه فعلی خط تولید کاشی نیست.
- [ ] ابتدا پردازش خودمیزبان OSM را ارزیابی؛ مجوز، انتساب، هزینه/ظرفیت، بررسی هفتگی قابل تنظیم و انتشار را تعیین کنید.
- [ ] تعیین ذخیره‌سازی، Cache، تعویض نسخه و دسترسی؛ تعریف نقش جدا برای مدیر سازمان و تیم GeoCore؛ تعیین مسئولیت هر مدل استقرار.
- [ ] انتخاب محدوده و مرجع مجاز آزمون در پنج شهر و ثبت محدودیت تعمیم.
- [ ] پیاده‌سازی اعتبارسنجی داده و سرویس، کنترل دسترسی، Cache و مشاهده‌پذیری امن پس از تصویب طراحی.
- [ ] اجرای آزمون نمایشی، فارسی/انگلیسی، خالی/خارج پوشش/خطا، دو مدل میزبانی، داده عمومی/خصوصی، جداسازی سازمان، بازگشت و اهداف مصوب.

## کارهای Routing

- [x] جهت مالک: هر دو موتور OSRM و Valhalla قابل انتخاب سازمانی؛ سه پروفایل پایه و چندمقصدی/بهینه‌سازی حفظ؛ بازگشت اختصاصی به مبدأ از نسخه نخست کنار گذاشته شد.
- [ ] مسئول نمونه‌سازی و شبکه مرجع مجاز و محیط مجزای هر دو موتور فراهم شوند؛ محیط فعلی Docker/Podman، اجرایی OSRM/Valhalla و داده شبکه ندارد.
- [ ] ماتریس امکان‌سنجی هر دو موتور و نسخه/پیکربندی برای هر پروفایل، ترتیب، دو حالت مقصد پایانی، شکست و محدودیت منتشر شود.
- [ ] منبع شبکه مستقل، مجوز، رفتار پروفایل و مرجع مسیر تعیین شود.
- [ ] قرارداد چندمقصدی و نگاشت توقف تکراری، سقف، جابه‌جایی نقطه و رد گزینه پشتیبانی‌نشده تعیین شود.
- [ ] هزینه، هندسه، زمان، دسترس‌ناپذیری، نسخه سازگار و خطای موتور آزموده شوند؛ شکاف قابلیت به مالک گزارش شود.

## کارهای موقعیت و تاریخچه

- [ ] پیش از داده مکانی واقعی، بازبینی حقوقی و حریم خصوصی سناریو کامل و مسئولان تعیین شوند؛ تا آن زمان داده آزمایشی مجاز.
- [ ] وب نخستین کلاینت؛ محدوده SDKهای بومی Android/iOS، نسخه‌های هدف و شواهد هر پلتفرم تعیین شود؛ برنامه کامل رابط‌دار مفروض نیست.
- [ ] بافر نخستین انتشار تاریخچه با پیش‌فرض روشن ولی قابل خاموش‌کردن؛ سقف صف، رمزگذاری و مهلت سفر باز تعیین و آزموده شود.
- [ ] نمونه دیررس فقط در پنجره سازمانی سفر باز؛ پایان تاریخچه اتمی و تغییرناپذیر باقی بماند.
- [ ] تشخیص بی‌حرکتی ۲۴ساعته تا اعتبارسنجی در نمونه آزمایشی خاموش؛ فاصله نمونه و داده مرجع تعیین شود.
- [ ] اشتراک حساب و پیوند مهمان در انتشار نخست؛ برون‌سازمانی/پیوند تا فعال‌سازی سازمانی خاموش؛ تازگی و لغو آزموده شوند.

- [ ] مسئول حقوقی/حریم خصوصی، مالک محصول، فنی، عملیات، سرویس‌ها و بازبینان فارسی/انگلیسی نام‌گذاری شوند.
- [ ] هدف‌ها پس از آزمون واقعی تصویب و SLI/SLO از SLA جدا شوند.
