# مبنای پشته توسعه

**وضعیت:** مالک محصول این مبنا را برای کد برنامه و APIهای GeoCore تعیین کرده است. این سند جهت فناوری را ثبت می‌کند؛ اثبات نمی‌کند که سرویس یا APIای از GeoCore پیاده‌سازی یا منتشر شده باشد. نسخه ابزار و ادغام وابستگی‌ها باید در هر بسته کاری تثبیت و بازبینی شود.

## پیش‌فرض‌های لازم

- **محیط اجرا و مدیر بسته:** برای کد برنامه TypeScript، اسکریپت‌ها و نصب وابستگی‌ها از Bun استفاده شود و فایل قفل `bun.lock` در مخزن باشد؛ CI نصب قفل‌شده انجام دهد. کد برنامه و نمونه‌سازی با JavaScript نوشته نشود و TypeScript باشد. ابزار مستندسازی Python از این قاعده کد برنامه مستثناست.
- **زبان:** TypeScript با گزینه `strict` برای کد برنامه، نمونه‌سازی و آزمون. بررسی کامپایلر بخشی از اعتبارسنجی بسته باشد.
- **آزمون:** برای همه فایل‌های آزمون پروژه از Vitest استفاده شود؛ آزمون‌ها با TypeScript و پسوند `*.test.ts` نوشته شوند و خود Bun زمان اجرا باشد. بسته‌های فعلی Vitest را با Bun و thread pool (`--pool=threads`) اجرا می‌کنند و آزمون نگهبان زمان اجرا دارند. برای آزمون‌های پروژه از test runner داخلی Node.js استفاده نشود؛ با ارتقای Bun یا Vitest، فرمان و pool دوباره بررسی شود.
- **APIهای HTTP:** چارچوب لازم برای پیاده‌سازی APIهای HTTP در GeoCore، Fastify است. این مبنا هیچ قرارداد API، endpoint یا سرویس پیاده‌سازی‌شده‌ای ایجاد نمی‌کند.
- **اعتبارسنجی و نوع‌ها:** کتابخانه لازم برای شِمای اعتبارسنجی API و استنتاج نوع TypeScript، Zod است. داده نامطمئن در مرز ورودی parse شود؛ نوع دستی جداگانه‌ای که ممکن است از شِمای اعتبارسنجی جدا شود تعریف نکنید.

## قواعد ادغام و ایمنی

- پیش از ساخت الگوی API قابل استفاده مجدد، سازگاری Bun + Fastify + Zod را با نمونه‌ای کوچک و جداگانه بررسی کنید. هر type-provider یا adapter برای Fastify و Zod فقط پس از بررسی نگهداری، سازگاری زمان اجرا، نوع‌دهی، هشدارهای امنیتی و مجوز انتخاب شود؛ این سند adapter یا نسخه‌ای را انتخاب نمی‌کند.
- نوع‌ها را از همان شِماهای Zod به‌کاررفته برای اعتبارسنجی زمان اجرا استخراج کنید. نوع‌دهی درخواست/پاسخ Fastify باید با اعتبارسنجی واقعی هماهنگ باشد؛ نوع‌های زمان کامپایل ورودی شبکه را اعتبارسنجی نمی‌کنند.
- قرارداد API، احراز هویت/مجوز، مرز سازمان‌ها، معنای خطا، محدودیت منابع، استقرار و پردازش داده باید در مشخصات بازبینی‌شده هر سرویس بیایند. Fastify و Zod این تصمیم‌ها را تعیین نمی‌کنند.
- هر سرویس GeoCore باید مستقل قابل استفاده باشد؛ موتور، داده یا زیرساخت بیرونی فقط به‌عنوان پیش‌نیاز صریح و مستند مجاز است.
- وابستگی‌ها را در فایل قفل Bun تثبیت کنید، مجوز مستقیم و انتقالی و هشدار امنیتی را بررسی کنید و با تغییر وابستگی آزمون‌ها را دوباره اجرا کنید. نتیجه audit مقطعی است و تأیید حقوقی یا تضمین امنیت آینده نیست.

## وضعیت فعلی مخزن

نمونه‌های ماتریس کاشی و MVT مصنوعی از JavaScript و test runner داخلی Node به TypeScript Strict و Vitest زیر Bun منتقل شده‌اند. نمونه سازگاری جداگانه نیز بررسی TypeScript Strict و پنج آزمون Vitest را با Fastify 5، Zod 4 و اتصال نامزد `fastify-type-provider-zod` زیر Bun می‌گذراند. این adapter برای تولید تصویب نشده است. هیچ API یا سرویس GeoCore پیاده‌سازی نشده؛ قرارداد سرویس و آمادگی تولید همچنان بازند.
