# حاکمیت داده و منشأ

**وضعیت:** مبنای کاری و چرخه پیشنهادی؛ این مخزن هنوز داده‌ای تهیه، اعتبارسنجی یا منتشر نکرده است. ترجمه‌پیش‌نویس، نیازمند بازبینی انسانی/فنی.

## شناسنامه لازم برای هر داده

هر داده نامزد یا منتشرشده باید شناسنامه نسخه‌دار داشته باشد: مالک و منبع و روش دریافت؛ نسخه دقیق مجوز و تعهد انتساب/اشتراک مشابه؛ پوشش جغرافیایی و موضوعی؛ زمان مشاهده/اعتبار و دریافت؛ زمان پردازش/انتشار؛ نسخه داده و ابزار پردازش؛ شکاف‌ها و روش سنجش کیفیت؛ استفاده و بازتوزیع مجاز؛ ملاحظات داده مشتق‌شده؛ مسئول؛ نگهداری و حذف. مقدار نامعلوم را «نامعلوم» ثبت کنید، نه حدس.

## OSM و منابع بیرونی

مالک محصول OSM را منبع اولیه و بررسی مسیر پردازش خودمیزبان را اولویت داده است؛ هیچ‌کدام روش دریافت یا مجازبودن استفاده خاصی را تصویب نمی‌کند. مجوز پایگاه داده ODbL را از شرایط عملیاتی Nominatim و سرور کاشی عمومی جدا کنید. هنگام اجرا سیاست‌ها و ملاحظات مجوز را دوباره بررسی کنید؛ دریافت انبوه یا ساخت بسته آفلاین با سرور عمومی کاشی raster را برخلاف سیاست آن انجام ندهید. انتساب و آثار اشتراک مشابه را برای هر ترکیب و خروجی جداگانه بسنجید و در ابهام از مشاور حقوقی واجد صلاحیت کمک بگیرید.

تمرکز نمونه اولیه روی تهران، کرج، تبریز، مشهد و اصفهان است و بررسی نمونه روستا و شهر کوچک به مرحله بعد موکول شده؛ هدف محصول همچنان ایران است. این پنج شهر دقت سراسری را اثبات نمی‌کنند. محدوده دقیق، داده مرجع مجاز، سناریو و مالک بررسی باز است.

## چرخه انتشار داده

`پیشنهادی ← دریافت‌شده ← اعتبارسنجی‌شده ← آماده‌شده ← نامزد ← تأییدشده ← منتشرشده ← جایگزین/پس‌گرفته‌شده`

هر گذار باید شواهد و مسئول داشته باشد. نامزد ناموفق را از داده فعال جدا کنید. منشأ، قالب، یکپارچگی، پوشش، شِما و کیفیت نمونه‌ای را بررسی کنید. نسخه منتشرشده تغییرناپذیر و قابل بازگشت باشد؛ مصرف‌کننده نسخه مؤثر را بتواند تشخیص دهد. رفتار درخواست در حال اجرا و Cache هنگام تعویض نسخه تعریف شود. الزامات حذف و پایان مجوز برای داده فعال، مشتق، Cache و پشتیبان اعمال می‌شود.

## کیفیت و تناوب به‌روزرسانی

بررسی به‌روزرسانی هفتگی به‌صورت پیش‌فرض و قابل تنظیم است؛ این به معنی تغییر هفتگی داده یا مناسب‌بودن خودکار نسخه تازه نیست. زمان مشاهده منبع را از دریافت، پردازش و انتشار جدا ثبت کنید. پوشش و کیفیت را با مرجع نسخه‌دار منطقه‌ای بسنجید؛ داده نامعلوم صفر نیست. تازگی، پوشش، منابع و هدف‌های به‌روزرسانی پیش از انتشار تصویب شوند.

## فهرست انتشار مجموعه داده

- [ ] منبع، محدوده، مجوز، انتساب و حق بازتوزیع بررسی شده‌اند.
- [ ] شناسنامه کامل و نسخه‌دار و منشأ قابل پیگیری است.
- [ ] اعتبارسنجی یکپارچگی، شِما و جغرافیا موفق و داده نامعتبر جدا شده است.
- [ ] پوشش و کیفیت با مرجع نسخه‌دار مصوب بررسی شده‌اند.
- [ ] سازگاری با مصرف‌کننده، سبک، فونت و زبان بررسی شده است.
- [ ] امنیت، جداسازی سازمان و Cache ارزیابی شده‌اند.
- [ ] انتشار، بازگشت، حذف، نگهداری و پشتیبان آزموده شده‌اند.
- [ ] اثر بر کاربران و اپراتورهای فارسی و انگلیسی مستند شده است.

ردیابی: `REQ-D1` تا `REQ-D6`، `MANAGE-01`، `TILE-01` و `OPS-05`.
