# ثبت بازبینی حقوقی، حریم خصوصی و مجوز

**وضعیت:** فهرست بازبینی است، نه مشاوره یا نظر حقوقی، مجوز استفاده یا تشخیص شمول قانون. سرویس یا داده منتشرشده‌ای در مخزن وجود ندارد. پیش از پردازش/انتشار تولیدی، بررسی متخصص برای سرویس، مشتری، منبع و حوزه مربوط لازم است. ترجمه‌پیش‌نویس و نیازمند بازبینی است.

## ارزیابی شمول قانون — مانع انتشار

مالک محصول تمرکز اولیه بررسی حقوقی/حریم خصوصی را ایران تعیین کرده است؛ سایر حوزه‌ها در صورت کاربرد بررسی شوند. تا تکمیل بازبینی حقوقی و حریم خصوصی برای سناریوی مشخص، موقعیت واقعی افراد پردازش نشود و از داده آزمایشی مجاز استفاده شود. این قاعده نتیجه‌گیری درباره اینکه کدام قانون ایران اعمال می‌شود نیست.

برای هر سرویس و مدل میزبانی، نهاد مسئول و نقش‌ها، اشخاص، هدف، نوع داده، محل کاربر و موضوع داده، محل میزبانی/پشتیبانی، پیمانکار، جریان و مدت نگهداری/حذف، محل انتقال/دسترسی و حوزه‌های محتمل ثبت شوند. بررسی تخصصی شامل موارد زیر باشد:

- آیا GDPR یا قانون اروپا/منطقه اقتصادی اروپا با توجه به نهاد و پردازش واقعی اعمال می‌شود؟ در صورت کاربرد، مبنای قانونی، شفافیت، حقوق، قراردادها، امنیت، نیاز ارزیابی اثر و انتقال بین‌المللی بررسی شود.
- کدام قوانین ایران درباره حریم خصوصی، امنیت سایبری، مخابرات، نقشه/مکان، مصرف‌کننده یا محل نگهداری داده بر سناریو منطبق‌اند؟ مشاور حقوقی محلی باید شمول و تکلیف را تأیید کند؛ این مخزن حکم حقوقی صادر نمی‌کند.
- محدودیت انتقال، تحریم/کنترل صادرات، پرداخت، میزبانی و قرارداد ارائه‌دهنده برای بازار هدف چیست؟ در صورت کاربرد متخصص بررسی کند؛ این فهرست به‌تنهایی مجوز یا منع نمی‌سازد.
- حوزه دیگری که به‌سبب اپراتور، مشتری، کاربر، میزبانی، منبع یا افشای داده مطرح می‌شود.

هر مورد «مشمول»، «نامشمول با دلیل» یا «حل‌نشده» ثبت شود؛ ابهام مهم، انتشار تولیدی را متوقف می‌کند.

## حقوق داده و نرم‌افزار

برای هر داده پایه، مشتق، مرجع و ورودی کاربر، منبع، نسخه مجوز، تاریخ/روش دریافت، هدف مجاز، بازتوزیع، انتساب، تعهد پایگاه/داده مشتق، ترکیب، نگهداری/حذف و مالک ثبت شود. ODbL مربوط به OSM را از سیاست استفاده سرویس عمومی جدا بررسی کنید؛ دسترسی به API یا کاشی به‌خودی‌خود مجوز استفاده پایین‌دستی نیست. درباره پایگاه مشتق، خروجی، ترکیب، میزبانی و بسته آفلاین نظر حقوقی بگیرید. مجوز وابستگی نرم‌افزاری و فهرست اجزا نیز با انتشار نگهداری شود.

## موقعیت شخصی و حقوق کاربران

پیش از تاریخچه، اشتراک یا نزدیکی، هدف، نقش کنترل‌گر/پردازش‌گر، مبنای قانونی، اطلاع، گیرنده، حداقل دقت، نگهداری، حذف، دسترسی و حقوق افراد، اعتراض/لغو، شکایت و رخداد نقض ثبت شوند. رضایت همیشه تنها یا مناسب‌ترین مبنا فرض نشود. اشتراک بدون زمان پایان به معنی نگهداری نامحدود یا رضایت کلی نیست. نیاز ارزیابی اثر یا مشورت قبلی سنجیده شود.

## رکورد تأیید هر انتشار

| فیلد | چیزی که باید ثبت شود |
|---|---|
| سرویس/نسخه و میزبانی | محدوده دقیق و مناطق پشتیبانی |
| داده/نرم‌افزار | فهرست منبع، نسخه مجوز، انتساب و کاربرد بررسی‌شده |
| حوزه و شمول | نظر مشاور، پرسش باز و دلیل |
| نقش و هدف داده شخصی | نهاد مسئول، هدف، مبنا و اطلاع‌رسانی |
| انتقال/پیمانکار | طرف، محل، حفاظت و تأیید لازم |
| نگهداری/حذف | داده اصلی، مشتق، لاگ، Cache، پشتیبان و بازیابی |
| بازبین/تأیید | مالک محصول، امنیت/حریم خصوصی و حقوق؛ نام، تاریخ و مدرک |
| شرط | محدودیت، تعهد مشتری، مسئول پیگیری و زمان بازبینی |

ردیابی: `REQ-D5/D6`، `REQ-P2` تا `REQ-P5`، `HIST-05` تا `HIST-10`، `SHARE-01` تا `SHARE-13` و `SEC-03` تا `SEC-05`. با تغییر داده، هدف، حوزه، میزبانی یا گیرنده، ارزیابی تکرار شود.
